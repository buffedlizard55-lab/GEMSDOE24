# Standing project instructions

Read the entire root README and its standing owner charter at the start of every
session. Maximize P(Win) and Own the Outcome, without promising a score or prize.

- Use the active pipeline and evidence; legacy scripts/reports are historical,
  not promotion authority.
- Preregister physical hypotheses before implementation. Do not silently tune
  outer folds or change a negative result into a new success.
- Audit labels first using only the required nuisance families. Missing true
  operational blocks or nearest-road source coverage must remain blocked.
- Fit nuisance removal/scaling on training-region data only; refit and re-audit
  the exact emitted candidate. Association is not causation.
- No weekly slot unless the candidate beats the CURRENT reproduced comparable
  holdout best and passes the full exact-file audit. Format green is not gate green.
- Keep owner-reported scores, official snapshots, local diagnostics and hypotheses
  distinct. Preserve unknowns, hashes, negative results and source limitations.
- Keep the first-screen download clear, uniquely named and [0,1]-validated, with
  separate short comment and executive guide. A renamed reference is not new work.
- Review three times; preserve source links and blocked acceptance items. Do not
  claim a PR, merge or public deployment without evidence. Never request secrets.
- Keep large regenerable inputs/caches out of Git; retain only the small artifacts
  necessary for auditable scientific results.
